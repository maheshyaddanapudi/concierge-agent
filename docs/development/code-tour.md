# Code Tour

A guided walk through the codebase. Spec section references (`§n`) point into `spec.md`.

The shape in one paragraph: `backend/app/` is a FastAPI application with **23 top-level modules** (cross-cutting concerns — configuration, the database, observability, the registry cache, the egress and untrusted-input choke points, the cluster primitives) and **15 packages** (the tiers and the subsystems). `frontend/src/` is a React admin with **11 pages**, two of them shown only while their master switch is on. Nothing outside `app/llm/` imports a provider SDK (§2.1) and nothing outside `app/auth/` reads the auth switch (§20) — both are asserted by test.

## Backend — `backend/app/`

### Top-level modules

**The application shell**

- **`main.py`** — FastAPI application factory (`create_app`) and startup lifecycle: run Alembic migrations, load seeds, create checkpointer tables, warm the registry cache, start the MCP manager, the ambient loop, the periodic job loop and the embeddings backfill as non-blocking tasks. Mounts `/health` (liveness), `/ready` (admission + database) and Prometheus `/metrics`, and installs the CORS, auth and request-limit middleware. Migrations and seeding run under a boot lock so N replicas do them once (§18.9).
- **`config.py`** — `AppConfig` (pydantic-settings): env-only configuration and secrets (§13), 44 fields. Treats blank env strings as "unset" so compose's `${VAR:-}` passthrough never produces a falsely-configured provider.
- **`db.py`** — async SQLAlchemy engine/session factory, the shared LangGraph Postgres checkpointer (`get_checkpointer` / `close_checkpointer`), the declared connection budget (`DB_POOL_SIZE` + `DB_MAX_OVERFLOW` + checkpointer pool + session connections, checked at boot), and `reset_db_state` for tests.
- **`limits.py`** — inbound request limits: an unconditional body-size cap (`MAX_REQUEST_BYTES`) and upload caps (`MAX_UPLOAD_BYTES`, `MAX_EVAL_ROWS`). The outermost middleware — a body is bounded before any handler sees it.
- **`ratelimit.py`** — the distributed token bucket in `rate_buckets` (§18.8, M54), so N replicas grant one budget. Fails **open** with a log: availability over a limit the pool already bounds.

**Cross-cutting policy**

- **`obs.py`** — observability (§10): structlog JSON logging, 45 Prometheus series, OTel spans, per-run LangSmith tracer, the `run_scope` context manager that binds `run_id`/`mode` for a whole run — all carrying the shared label set (`run_id, step_id, tier, kind, source, entity_id, entity_name, model, effort, …`).
- **`egress.py`** — one policy for **every** outbound fetch made on someone else's say-so (A2A cards and calls, poll sources, HTTP MCP servers, the webhook channel): `EGRESS_POLICY` public / allowlist / open, judged by literal address and by resolution, re-checked on every redirect hop, bodies streamed under `EGRESS_MAX_BYTES`, one refusal shape (M52).
- **`untrusted.py`** — the **one** fencing choke point (M52): every string an external party authored is rendered through `fence_body` / `render`, which neutralizes fence-shaped tags inside the payload and stamps a per-render token on both tags, so a payload can neither close the fence early nor forge one.
- **`sanitize.py`** — one exception-text sanitizer (M52): redacts known secret values and credential shapes before any error is persisted, returned, or logged.
- **`cost.py`** — the cost model and the shared **spend ceiling** (M53): per-run cost priced from captured usage, `enforce_spend_ceiling` at every run entry point, and for work that is not a run: `enforce_job_ceiling` (the same one ceiling, checked at the job's entry point), `record_job_usage` (one `job_usage` row per out-of-run model call, priced when it happens) and the `job_spend` context manager that wraps the two.
- **`retention.py`** — retention for the nine tables nothing else trims (`ambient_events`, `deliveries`, `ambient_policies`, `pattern_instances`, `a2a_tasks`, `auth_sessions`, plus `checkpoints` / `run_steps` / `runs`), each behind its own §3.7.1 gate enforced in-function, previewable and runnable from Settings.

**Registry, retrieval and documents**

- **`registry_cache.py`** — the M7 cache layer (§7.3): singleton `RegistryCache` facade over every registry/settings read in the run path, with live-swappable backends (`memory` — the shipped default — / `bypass` — the live-read rollback lever — / `redis`), per-registry generation counters, reload-on-dirty, a `REGISTRY_CACHE_TTL_S` expiry so a lost invalidation costs bounded staleness, `pg_notify` cross-replica invalidation with origin filtering, fail-open to Postgres with a degraded counter, and the `invalidate` / `refresh` / `status` operations behind `/api/v1/cache/*`.
- **`retrieval.py`** — progressive-disclosure retrieval (§7.4): BM25 + embedding-cosine scoring fused by RRF over the cache snapshot, threshold gate, pinned ids, truncation footers, write-path embedding maintenance and the startup `backfill_embeddings` task.
- **`settings_store.py`** — `app_settings` defaults (122 keys), live reads, and validated writes (§3.7); a PATCH applies to the next run with no restart and invalidates the settings cache.
- **`skilldoc.py`** — skill document parsing (§3.3): frontmatter + markdown body, `{tool:...}` mention extraction/validation, and the `.skill.md` startup scan — one format shared by native files and UI-authored custom skills.
- **`agentdoc.py`** — `.agent.md` parsing (§3.4): frontmatter + the §3.5 workflow with skill-by-name resolution, for declarative static custom sub agents.
- **`doclint.py`** — offline lint for `.skill.md` / `.agent.md` (`python -m app.doclint`): the same checks the seed applies, wired as a pytest gate **and** a Docker build gate, so a malformed document fails the build instead of landing as `status='error'` at boot.
- **`toolschema.py`** — tool schema fingerprints (§3.2 drift): every write of `input_schema` is fingerprinted and versioned; a change is logged, counted and flagged until acknowledged, and under `mcp_schema_change_policy=quarantine` takes the tool out of service.
- **`overlap.py`** — the LLM-as-judge overlap guard (§4) backing `POST /skills/check-overlap` and `/sub-agents/check-overlap`, plus the periodic registry overlap audit: builds candidate lists (skills vs skills+tools, sub agents vs sub agents+skills), runs the fenced `overlap_judge.md` prompt through the provider port with structured `OverlapVerdict` output, and fails open on any judge trouble (the API reports `judge_available: false` rather than a bare 0 %).

**Cluster primitives (M54, §18.9)**

- **`replica.py`** — this process's `replica_id`, its heartbeat row in `replicas`, the boot advisory lock, and the fleet reads (who is live, who owns what).
- **`control.py`** — the one LISTEN/NOTIFY control channel carrying the three cluster-wide facts: a cancel intent for a run executing elsewhere, a terminal transition a stream held elsewhere is waiting for, and an in-app delivery every replica must re-fan.
- **`listen.py`** — supervised LISTEN connections with backoff, reconnect hooks, a named `application_name` and the `concierge_listener_connected` / `_reconnects_total` signals.
- **`jobclock.py`** — the persisted job clock (`job_clock`): an interval is a property of the cluster, not of a process's monotonic clock, so a restart re-runs nothing.

### Packages

- **`api/`** — one router per resource, aggregated in `api/__init__.py` under `/api/v1` (86 paths, 115 operations): `mcp_servers.py`, `tools.py`, `skills.py`, `sub_agents.py` (registries, §4), `remote_agents.py` (§19), `chat.py` (conversations, `POST /chat`, the SSE stream with `Last-Event-ID` resume and record resolution, HITL resolve), `runs.py` (list/detail/cancel/retry/delete/purge), `memories.py` (§16 store, recall, tombstones, purge), `routines.py` (+ `presence_router`, §17), `ambient.py` (three routers: deliveries, watches, the policy ledger), `evals.py` (§15), `auth.py` (§18.8/§20), `settings.py` (+ providers, HITL pending queue), `ops.py` (spend, retention, replicas), `seed.py` (idempotent reload), `cache.py` (cache status/refresh, §8.7), `fake_llm.py` (`/_fake` script control, mounted only when `FAKE_LLM_ENABLED`), and `deps.py` (shared list filters + static-record write rules).
- **`models/`** — SQLAlchemy ORM, **40 tables** (`len(Base.metadata.tables)`, 2026-09-14 — the 38 entity tables plus the `skill_tools` and `sub_agent_skills` association tables) across 13 modules: `base.py` (`Base`, `RegistryRecord`), `mcp_server.py`, `tool.py`, `skill.py`, `sub_agent.py`, `run.py` (`Conversation`, `Run`, `RunStep`), `setting.py`, `memory.py` (§16 — memories, embeddings, entities, links, tombstones, digests, rollups, exemplars, routing stats), `cluster.py` (`replicas`, `job_clock`, `rate_buckets`), `ambient.py` (§17 — events, routines, standing intents, deliveries, policies, patterns, wakeups, presence), `eval.py` (§15), `remote_agent.py` (§19), `user.py` (§18.8). Full map: [architecture/data-model.md](../architecture/data-model.md).
- **`schemas/`** — Pydantic v2 API schemas, deliberately separate from ORM models (§13): `common.py`, `mcp_server.py`, `tool.py`, `skill.py`, `sub_agent.py`, `memory.py`, `remote_agent.py`.
- **`llm/`** — the provider layer (§2.1), **the only module tree allowed to import provider SDKs**. `port.py` (the `ModelProvider` protocol, `ModelParams`, `ModelInfo`), `registry.py` (`@model_provider` registration, the single entry points `get_model()` / `get_embeddings()`, save-time validation), `adapters.py` (anthropic / google_genai / openai / openrouter / custom wrappers with effort→provider-knob mapping and the shared `port_limits()` timeout+retry budget), `fake.py` (the scriptable `fake:scripted` provider tests and keyless demos use), `content.py` (provider-neutral extraction of text from reasoning-block message content), `metrics.py` (per-call latency and outcome by provider/model from one LangChain callback at the port), `pricing.py` (the built-in reference price table).
- **`auth/`** — the fork seam (§20, M55): `port.py` (the eight-member `AuthProvider` protocol), `registry.py` (`@auth_provider` registration, `AUTH_PROVIDER` / `AUTH_PROVIDER_MODULE` selection), `builtin.py` (the §18.8 behaviour — scrypt passwords, hashed bearer sessions, the tenancy predicate — dark unless `AUTH_ENABLED`). The forker's guide is [extending.md](../extending.md).
- **`mcp/`** — `manager.py`: the singleton MCP connection manager (§5). One asyncio task per active server holding the client session; `tools/list` ingest into the tools registry (idempotent, operator-intent preserving), `listChanged` reconciliation, health ping loop, reconnect with backoff and a **circuit breaker**, the stdio launcher allowlist (`MCP_STDIO_ALLOW`), and LangChain tool objects for the factory.
- **`factory/`** — the worker factory (§6). `dag.py` validates workflow DAG structure at save (single START, path to END, no cycles, unique nodes, ≤1 error edge per node). `worker.py` compiles a sub-agent snapshot into a LangGraph `CompiledStateGraph`: explicit StateGraph shell (routing, error edges, `Send` fan-out, joins, `interrupt()`), `create_agent` tool loops at skill nodes, prompt assembly in spec order (`assemble_skill_prompt`), model resolution order skill→agent→defaults (`resolve_node_model`), and the condition router LLM call. The compiled-worker cache is keyed on the agent id, its `updated_at` **and a digest of the bound skills' definition hashes and statuses** — a skill edit or toggle invalidates it (third reading).
- **`native/`** — code-defined capabilities (§5b): `provider.py` (the `@native_tool` / `@native_sub_agent` decorator scan, schema derivation, guardrails), `tools.py` (`summarize-and-structure`, `render_chart`), `memory_tools.py` (`memory.remember` / `.recall` / `.forget`), `ambient_tools.py` (`ambient.wakeup` / `.cancel_wakeup` / `.watch` / `.confirm_watch` / `.unwatch`), `agents.py` (the native `workspace-warden` sub agent), `skills/*.skill.md` (five seeded skill documents: `web-research`, `file-ops`, `memory-keeper`, `workspace-auditor`, `workspace-curator`), `sub_agents/workspace-reporter.agent.md` (the declarative example). **Ten native tools, five native skills, one native sub agent.**
- **`orchestrator/`** — §7 end to end. `runner.py` (run lifecycle: asyncio task per run, admission slot, heartbeat, wall clock, cooperative cancel, HITL pause/resume on the checkpointer, the reapers for orphaned and dead-owner runs); `admission.py` (`run_max_concurrent` semaphore, `run_queue_max` queue, the `queued` status, drain state); `graph_mode.py` (plan→resolve→dispatch→aggregate StateGraph); `agentic_mode.py` (single `create_agent` concierge with the full middleware stack); `direct_mode.py` (§7.5 pinned sub-agent invocation); `planner.py` (progressive-disclosure prompt, structured plan output, validate→repair-once→fail); `ladder.py` (deterministic capability resolution: direct → native → custom → ephemeral worker, plus execution of each rung); `middleware.py` (the three registry-projection middlewares and `build_middleware_stack`); `answer_ui.py` (model-generated component tree → deterministic A2UI v0.9 translation, with chart validation at the boundary); `snapshot.py` (the run's frozen registry/settings/prompt/context pin); `recorder.py` (run/step recording + every observability emission); `context.py` (the per-run contextvar `RunContext` and the bounded, TTL-evicting `RunEventBus`).
- **`memory/`** — §16 CoALA-shaped memory behind `memory_enabled`. `store.py` (L2 semantic writes, bi-temporal supersession, the admission gate), `extract.py` (the L2 write pipeline: extraction, reconciliation, instruction quarantine), `extract_learn.py` (the M47 extraction tuner), `episodic.py` (L1 run digests + conversation rollups + compaction), `procedural.py` (L3 plan exemplars, vote lifecycle, fallback mining), `rank.py` (hybrid FTS + vector recall, RRF, absolute-similarity scoring), `inject.py` (prompt-assembly injection with per-section budgets and fencing), `feedback.py` (citation feedback — only cited memories reinforce), `communities.py` (§18.6 label propagation + summaries), `lifecycle.py` (the L4 consolidation jobs and the periodic job map, each gate enforced in-function), `scheduler.py` (the post-run pipeline and the advisory job locks), `dims.py` (typed per-dimension embedding columns with their HNSW indexes).
- **`ambient/`** — §17/§18 ambient mode behind `ambient_enabled`. `store.py` (the event store with cascade guards and the wake NOTIFY), `triggers.py` (schedule / poll / state-edge / webhook evaluators with catch-up watermarks and AIMD pollers), `sources.py` (native poll sources and state probes, §18.3), `patterns.py` (CEP-lite composite patterns with armed-timer absence), `decide.py` (the three-tier fire/hold gate with the significance judge), `execute.py` (fires become ordinary runs with trigger provenance, narrowed projection, budgets and abstain; the stalled-run reaper), `wakeups.py` (agent-scheduled wakeups), `watch_compile.py` (the `ambient.watch` compile-echo-confirm compiler), `drain.py` (the claim→commit→process→write-back drain), `deliver.py` (the four-tier outbox: interrupt budget, quiet hours, bounded deferral, digest builder, supersede-collapse), `channels.py` (the `in_app` / `email` / `webhook` adapter registry with the retry ladder and dead-letter state), `presence.py` (the presence oracle — the literal audience of the toast), `salience.py` + `salience_learn.py` (§17.5 salience judging and the M45 tuner), `anticipate.py` (the only feature that initiates contact, behind its own gate), `learn.py` (the §17.7 reward-weighted bandit), `coordinate.py` (the leader lease on a dedicated session connection), `regex_guard.py` (the static guard and bounded matching for authored regexes).
- **`a2a/`** — §19 outbound A2A behind `a2a_enabled`. `manager.py` (card fetch, storage, per-card-skill tool projection with MCP ingest semantics, periodic refresh), `auth.py` (card-driven apiKey / basic / bearer / OAuth2 client-credentials placement via a standalone `ClientCallInterceptor`), `client_port.py` (the call-path port over the SDK client), `proxy.py` (the lazy `kind='a2a'` tool proxy with adopt-or-send idempotency), `tasks.py` (`a2a_tasks` bookkeeping), `poller.py` (the parked-task poller), `fence.py` (the §19 fence over every remote payload).
- **`evals/`** — §15. `parse.py` (csv/xlsx dataset parsing, bounded), `runner.py` (the batch runner over the existing run machinery, the reaper and the cancel path), `grade.py` (`exact` / `contains` / `llm_judge`), `publish.py` (LangSmith publication when configured).
- **`prompts/`** — every LLM prompt as a versioned `.md` file (27 today) plus the `load_prompt()` loader, the golden sets in `prompts/golden/`, and `check.py` (`python -m app.prompts.check` — a pytest gate and a Docker build gate). Catalog and rules in [prompts.md](./prompts.md).
- **`seed/`** — `loader.py`: idempotent static seed (§9), upserting on `(source='static', name)` so ids stay stable across reloads; scans the native providers, the `.skill.md` and `.agent.md` documents, and registers the two stdio MCP servers (`fetch`, `filesystem`) inactive.

Also: `backend/alembic/versions/` — **30 migrations** in one linear chain (verified by walking `down_revision` 2026-09-14), from `ebf05a862e33_initial_schema` to `x3l4m5n6o7p8_hardening_wave_two`; the full list with what each added is in [architecture/data-model.md](../architecture/data-model.md), which still stops at revision 29.

## Frontend — `frontend/src/`

- **`App.tsx`** — HashRouter shell: left nav, TanStack Query client, orchestrator-mode indicator, the login gate, the error boundary, and the lazy route split. Two nav entries are conditional — **Remote Agents** appears only while `a2a_enabled`, **Ambient** only while `ambient_enabled`.
- **`main.tsx` / `index.css`** — entry point and the Tailwind 4 theme tokens (mission-control default palette).
- **`theme.ts`** — client-side theme switching (§8.7): four palettes (`default`, `anthropic`, `openai`, `google`) applied via a `data-theme` attribute and persisted in localStorage behind a guarded accessor.
- **`api/client.ts`** — thin fetch wrapper over `/api/v1` (`ApiError` with detail extraction), the upload path, and the SSE subscription (`EventSource` on `/chat/stream/{run_id}` with `Last-Event-ID` resume).
- **`api/hooks.ts`** — TanStack Query hooks per resource: servers, remote agents, tools, skills, sub agents, runs, conversations, settings, providers, HITL pending, cache status/refresh, memories, routines, deliveries, watches, the ledger, evals, spend, retention and replicas.
- **`api/types.ts`** — the TypeScript mirror of the backend schemas and SSE event payloads, including `RunStatus` (`queued | running | paused_hitl | completed | failed | cancelled | stalled`) and the live/control predicates built from it.
- **`pages/`** — **eleven** pages: `ChatPage.tsx` (streaming chat, plan/todo cards, activity ticker, HITL cards incl. form gates, per-conversation target pin, Stop/queue, answer panel), `McpServersPage.tsx`, `RemoteAgentsPage.tsx` (card/skills/auth chips, write-only credential editor, the task drawer), `ToolsPage.tsx` (skill badges, expose toggle, schema drawer with the drift banner), `SkillsPage.tsx` (skill-document editor with preview and `{tool:}` autocomplete, overlap dialog, the "Saved unjudged" notice), `SubAgentsPage.tsx` (workflow builder with starter templates and react-flow preview), `RunsPage.tsx` (trace timeline, the Snapshot-vs-registry panel, cancel/retry/delete), `EvalsPage.tsx` (datasets, runs, results), `MemoryPage.tsx` (the §16 surfaces incl. review and the Forgotten tab), `AmbientPage.tsx` (the four §8.9 tabs), `SettingsPage.tsx` (the command center — sixteen sections).
- **`components/`** — eleven files: `RegistryTable.tsx` (the consistent table pattern of §8), `ui.tsx` (badges, pills, chips, drawer, toggle, masked values, and the rest of the primitive kit), `AnswerPanel.tsx`, `AnswerUiView.tsx` (official `@a2ui/react` renderer), `TableBlock.tsx` (the answer panel's table block), `ChartSvg.tsx` (themed pure-SVG bar/line/pie), `Markdown.tsx` (safe renderer, no raw HTML), `OverlapDialog.tsx`, `CacheControls.tsx`, `LoginGate.tsx` (the §18.8 sign-in gate), `AmbientToaster.tsx` (the tier-0/1 toast). The salience decision card is **not** a component file — it is `SalienceBlock` exported from `pages/AmbientPage.tsx`.
- **`test/`** — **14 vitest suites** (`ui`, `answer-ui`, `a11y`, `sse-seq`, `chat-pin`, `ambient-m30`, `ambient-toaster`, `a2a-m37`, `salience-card`, `settings-m40`, `settings-m53`, `schema-drift`, `hardening-wave`, `code-setting-ui`) with `setup.ts` for jest-dom.
